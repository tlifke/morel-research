# Paper card — Better Harnesses, Smaller Models

## One-paragraph summary

For routine business agentic tasks, much of the task difficulty is shared
across instances and can be lifted out of the model into the harness
(instructions, tools, hooks, orchestration). The authors build a meta-agent
"harness optimizer" that diagnoses SLM failure trajectories and proposes
harness edits, and show across 7 tasks × 3 SLMs that optimized harnesses
significantly improve 16/21 task-SLM pairs, with the best SLM recovering
~90% of frontier-LLM performance at ~4% of the cost.

## Claims

1. **Adaptation closes most of the gap.** Optimized harnesses significantly
   improve 16/21 task-SLM pairs; 7 pairs close the SLM-LLM gap entirely.
   Best SLM (gemma-4-26b-a4b) goes 31.4% → 80.2% average accuracy vs LLM
   89.7%, at $0.071 vs $1.735 per instance (4% of cost, 25% less latency).
   Per-task exemplar: budget-approval 75.0% → 98.3% vs LLM 97.3% at 8% cost.
2. **Task diversity predicts adaptation effectiveness.** Spearman ρ = −0.96
   between tool-call-sequence diversity and optimized score across tasks;
   controlled template-count experiment drops 89.1% → 68.0% as workflow
   templates go 3 → 20.
3. **Base capability predicts adaptation effectiveness.** More capable SLMs
   gain more (+48.8% vs +15.5%); harnesses cannot replace missing core
   capability (e.g. ministral-3-8b stays at 0% on stock-alert and
   anomaly-detection even optimized).
4. **Adaptations are explainable by a failure-mode framework.** Successful
   harnesses most often address instruction-following (81%) and knowledge
   (81%) failures, then tool-use (62%) and long-context (33%); dominant
   strategies are adding contexts (86%), creating tools (43%), managing
   tools (29%).
5. **Optimization cost amortizes.** $20 one-time optimization per run is
   recovered after ~13 deployment runs on average.
6. **Negative result: no successful sub-agent adaptations** were discovered;
   hypothesized SLM agent-management limitation (or meta-agent limitation).
7. **Harnesses don't transfer across SLMs.** Each model's failure patterns
   (e.g. qwen emitting XML instead of JSON tool calls, ministral file-edit
   failures) require tailored adaptations; re-optimize per model.

## Methods

- **Framework:** failure modes indexed by capability (tool-use,
  instruction-following, knowledge, long-context, planning/reasoning)
  mapped to adaptation strategies grouped by harness component (add/manage
  contexts, create/manage tools, instrument code, orchestrate agents).
- **Optimizer:** meta-agent (gemini-3.1-pro-preview) + GEPA-style genetic
  search over a harness pool sampled from the Pareto front. Loop: sample
  harness → evaluate on sampled training batch (full trajectories logged) →
  meta-agent diagnoses failures and edits harness code → sanity check →
  validate → add to pool. Search space = software-agent-sdk (OpenHands)
  components: system prompts/skills, tools (primitive/custom/scripts),
  hooks, context management, sub-agents.
- **Setup:** 7 tasks (100 instances each; website-management 50), 20/20/60
  train/val/test, 3 SLMs (qwen3-coder-30b-a3b, ministral3-8b,
  gemma-4-26b-a4b) vs gemini-3.1-pro-preview baseline on generic harness.
  $20 budget per optimization run, 3 runs per pair keeping best-validation
  harness ($1260 total), each final config evaluated 3× and averaged.
  Costs computed from token usage × official API pricing (Vertex/Bedrock).
- **Tasks** (from existing benchmarks, verifiable outcomes):
  attendance-auditing and budget-approval (TheAgentCompany templates),
  stock-alert and anomaly-detection (LOCA-Bench), playwright-testing
  (WebGenBench), website-management (WebArena CMS subset), code-refactoring
  (RefactorBench).

## Optimizer lessons the authors report (Section V-A)

- **Diagnosis quality is the bottleneck.** Raw JSON trajectories beat
  post-processed markdown summaries as meta-agent input; a cheaper
  meta-agent (flash) with more iterations produced worse harnesses.
  Hand-written adaptation heuristics and frontier example trajectories did
  not consistently help a strong meta-agent.
- **Exploration diversity over quantity.** Keep search memory of prior
  edits and outcomes; several independent searches beat one long one.

## Reproducibility assessment (our constraints: RTX 3080 12GB + ~$20)

**What transfers directly**
- Code is public (migration-analysis repo) and builds on the open
  OpenHands software-agent-sdk; task data derives from public benchmarks.
- Their per-optimization-run budget ($20) matches our total budget, so a
  single pair × single optimization run is in scope; their 3-runs-keep-best
  and the full 21-pair grid are not.

**What must be substituted**
- **SLMs:** gemma-4-26b-a4b (~16GB at Q4) and qwen3-coder-30b-a3b (~18GB
  at Q4) exceed 12GB VRAM; ministral3-8b-class dense models (~5GB Q4) fit,
  as do our existing 4B-class fleet. Substitution tests the *directional*
  claim, not their exact numbers.
- **Meta-agent:** they require a frontier meta-agent; we would use Claude
  via subscription, which changes cost accounting (their $20 covers
  meta-agent API + rollouts; ours would cover mostly rollouts).
- **Cost metric:** local inference has no API price; we would report
  wall-clock/energy or a synthetic API-equivalent price — a deviation to
  document.

**Recommended PoC slice**
- One low-diversity task (budget-approval: cheapest per-instance, largest
  documented win, concrete published example harness in Fig. 4) × one SLM
  that fits the 3080, single optimization run, reduced instance counts.
- **Key derisk question:** claim 3 predicts weak models benefit least —
  our study 006 (harness-adaptation floor) suggests a 4B may sit below the
  floor where adaptation pays off. The PoC doubles as a test of whether
  006's floor finding predicts this paper's RQ3 curve at 4B scale.

**Risks**
- Unverified whether the released repo includes task-instance generation
  pipelines (TheAgentCompany-derived templates) or only the optimizer.
- Their baseline/meta-agent is a closed API model (their own stated
  reproducibility threat); drift is expected.
- High run-to-run stochasticity acknowledged by authors; single-run PoC
  results need wide error bars in interpretation.

## Relevance to our work

- Direct external ground truth for studies/005-harness-rescue (same
  thesis: rich scaffolding rescues small models) and
  studies/006-harness-adaptation-floor (their RQ3 is our floor question).
- Their finding that raw JSON traces beat summarized markdown for agent
  consumers, while humans need the opposite, is direct evidence for the
  dual-artifact (agent-facing vs human-facing) design in study 007.
- Their negative sub-agent result parallels our inv-002 society/critic
  observations at small scale.
- Tension worth discussing: their bitter-lesson "harness design as search"
  framing vs our reasoner-not-optimizer north star; their own Lesson 1
  (diagnosis quality bottleneck) partially re-centers reasoning over search.

## Limitations (theirs, stated)

- Stochastic runs despite 3× averaging; findings tied to one task suite,
  three models, one optimizer implementation; clean environments with
  clear metrics; closed-API meta-agent hampers exact replication.
