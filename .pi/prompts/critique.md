This is the front door to the **visual-critique skill**. It is a prompt template
(`.pi/prompts/critique.md`), not a separate tool — it just fills in the skill's
required inputs.

Target: ${1:-MISSING}

What it is for, and what produces it: ${@:2}

FIRST, check the two lines above.

If Target says MISSING, or the "what it is for" line is blank, then STOP. Run
nothing, capture nothing, and do not guess a target. Reply with exactly this and
wait:

> `/critique` needs three things:
> 1. **Target** — a file path or URL, e.g. `./view_fixed.html` or `localhost:3000`
> 2. **Goal** — one sentence on what the page is for. This acts as the rubric.
> 3. **Source** — what code produces it, e.g. "generated by build_view.py"
>
> Example:
> `/critique ./view_fixed.html a researcher should see each pipeline step and its inputs/outputs — generated by build_view.py`

Only if BOTH lines are filled in, follow these steps exactly:

1. Capture the DEFAULT state with the screenshot-page skill.
2. Capture a SECOND state with `--js` that reveals hidden content — expand all
   `<details>`, open the first tab, dismiss any overlay. If the target genuinely
   has no hidden content, say so and skip this.
3. Report anything capture.py prints to stderr. A horizontal-overflow warning is
   itself a defect worth reporting.
4. Call survey_llms with BOTH `Qwen/Qwen3.8-27B` and
   `thinkingmachines/Inkling-Small`, `maxTokens=4000`, and ONE image per call.
   Loop over the tiles rather than sending them all together.
5. In the question, restate the goal and the source from above, then ask for the
   specific things that are broken or unreadable, what is seen and what to change
   in the source, only what is actually visible, as a short numbered list.
6. Merge the critics' findings. Discard anything you cannot point at in a PNG.
7. Present the merged list with the PNG paths. Do not fix anything.
